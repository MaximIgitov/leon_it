# Грейды и компетенции Software Engineer (разработчик)

Четыре грейда: Junior, Middle, Senior, Lead. Для перехода нужен уровень
«соответствует» по всем ключевым компетенциям грейда и подтверждение на
калибровке.

## Junior (0–1,5 года)

- Пишет код по задаче с понятными требованиями, покрывает тестами.
- Знает основы языка, работу с базой данных, HTTP и REST.
- Работает с git, проходит код-ревью, исправляет замечания.
- Ожидаем: вопросы задаёт рано, а не в конце спринта.

## Middle (1,5–4 года)

- Самостоятельно декомпозирует задачу среднего размера, оценивает сроки.
- Проектирует схему данных и API для своей функциональности.
- Понимает асинхронность, очереди, кэширование, транзакции и их компромиссы.
- Диагностирует инциденты по логам и метрикам, пишет постмортем.
- Ревьюит код коллег, объясняет замечания.

## Senior (4+ лет)

- Проектирует сервис целиком: границы, контракты, отказоустойчивость,
  наблюдаемость.
- Ведёт технический дизайн новой функциональности и защищает его перед
  командой.
- Оптимизирует производительность по измерениям, а не по догадкам.
- Наставляет middle-инженеров, отвечает за качество кода в команде.

## Lead

- Отвечает за техническое состояние продукта и дорожную карту техдолга.
- Принимает архитектурные решения с учётом стоимости и сроков.
- Растит инженеров, проводит калибровки, участвует в найме.

## Ключевые компетенции для Python-бэкенда

Язык и стандартная библиотека; асинхронность (asyncio, блокирующие вызовы);
базы данных (PostgreSQL, индексы, планы запросов, миграции); очереди и
интеграции (Kafka, RabbitMQ, идемпотентность); тестирование (pytest,
контрактные тесты); эксплуатация (Docker, CI/CD, логи, метрики, алерты);
безопасность (аутентификация, секреты, инъекции).

## Как проверяем на интервью

Просим рассказать реальный случай: «расскажите про сложный инцидент», «как вы
выбирали схему хранения», «что бы сделали иначе». Ценим конкретику: цифры,
инструменты, личный вклад, а не «мы».
