# LeonIT — план разработки

Платформа асинхронного видеоинтервью с ИИ-оценкой кандидатов. Кейс Napoleon IT
«ИИ-интервьюер: видеоинтервью и оценка кандидатов» (хакатон, сдача 07.09.2026).

Документ фиксирует границы продукта, архитектурные решения и последовательность
работ. Каждый пункт плана — отдельный PR в `main`; порядок важен, потому что
каждый следующий шаг опирается на предыдущий.

## 1. Что строим

**Сценарий из кейса.** Рекрутер загружает вакансию, требования и вопросы →
система выдаёт ссылку → кандидат проходит видеоинтервью (вопрос показывается и
озвучивается, ответ записывается на камеру) → транскрибация → ИИ-анализ →
структурированное заключение → рекрутер и нанимающий менеджер смотрят результат.

**Что добавляем сверх кейса** (по итогам разбора зарубежных платформ —
HireVue, Willo, myInterview, Spark Hire, BrightHire, Metaview, Karat):

| Область | Что делаем |
|---|---|
| AI-first интерфейс | Ассистент с инструментами в контексте страницы (как в Attio): создаёт вакансии, готовит и вычитывает вопросы, собирает срезовые отчёты, задаёт рекрутеру уточняющие вопросы. Свои подсказки-сценарии для каждой роли. |
| Кандидатский флоу | Имя, e-mail, согласие на обработку ПДн и политику конфиденциальности, чекбокс рассылки вакансий. Проверка устройств до интервью, подсказки по выдаче доступа к камере/микрофону для всех популярных браузеров и ОС. Тренировочный вопрос, время на подготовку, таймер ответа, прогресс. |
| Защита от фрода | Сигналы с клиента (уход с вкладки, потеря фокуса, выход из полноэкранного режима, вставка текста, смена устройств, число лиц в кадре по снимкам), серверный анализ (тишина/чтение с листа/ИИ-сгенерированный текст, аномалии тайминга, смена IP/устройства, дубли ответов между кандидатами). Итог — integrity-score и предупреждения в отчёте. |
| Уточняющие вопросы | Интервьюер может задать один аккуратный уточняющий вопрос после ответа (управляется настройкой вакансии). |
| Отчёты | Ранжированный список кандидатов по вакансии; карточка кандидата: видео по каждому вопросу с ускорением, транскрипт, саммари, скоры, сильные стороны, зоны роста, риски, навыки, что проверить дальше, предупреждения integrity, резюме, история диалога с HH. Кандидату — отдельная growth-обратная связь. Заметки и решения ревьюеров, режим «слепого» просмотра. |
| Дашборд | Метрики организации и каждой вакансии: воронка, конверсия, средние баллы, длительность, доля флагов, время до результата. |
| Интеграции | HH.ru через OAuth: импорт вакансий и резюме, автоматический первичный диалог в чате HH с выбором слота, уникальная ссылка на интервью. Huntflow: синхронизация вакансий, передача кандидатов и результатов. Публичный API с токенами и интерактивной документацией (Scalar). |
| Доступы | Роли: владелец/админ, рекрутер, нанимающий менеджер. Выдача доступа по ссылке-приглашению, отзыв, смена роли. Ссылки на отчёты для нанимающих менеджеров с ограниченным доступом и отзывом. |
| Задел на будущее | Слот под ИИ-аватар (интерфейс провайдера + место в UI), секция кода в интервью (тип вопроса `code`, редактор, интерфейс раннера). |
| Лендинг | Ориентирован на соискателя, с видеодемо интерфейса. |
| Эксплуатация | CI (линт, типы, юнит- и e2e-тесты), CD через self-hosted runner на сервере, HTTPS, миграции, health-чеки, регрессионный e2e-набор. |

## 2. Роли и границы доступа

| Роль | Что видит и делает |
|---|---|
| Владелец / админ организации | Всё, что рекрутер, плюс участники, роли, приглашения, интеграции, API-токены, настройки моделей. |
| Рекрутер | Вакансии, вопросы, кандидаты, приглашения, отчёты, дашборд, ассистент, HH-диалоги. |
| Нанимающий менеджер | Только те вакансии и кандидаты, к которым его допустили (членство с ограничением по вакансиям или ссылка на конкретный отчёт). Заметки и решение по кандидату. |
| Кандидат | Без аккаунта: ссылка-приглашение → согласия → проверка устройств → интервью → страница завершения. Growth-обратная связь по отдельной ссылке. |

## 3. Архитектура

```
leon_it/
├── backend/     FastAPI · SQLAlchemy 2 (async) · Alembic · uv · Python 3.12
├── frontend/    Next.js 14 (App Router) · TypeScript · Tailwind · shadcn/ui
├── e2e/         Playwright: регрессионные сценарии и запись демо-видео
├── deploy/      docker compose · Caddy (HTTPS) · скрипты выката
├── docs/        план, архитектура, runbook, юридические тексты
└── .github/     CI/CD
```

**Бэкенд — модульный монолит.** Каждая предметная область живёт в своём пакете
`backend/src/<area>/` с `models.py`, `schemas.py`, `service.py`, `router.py`.
Общая инфраструктура — `src/core/` (настройки, БД, безопасность, наблюдаемость,
фоновые задачи, хранилище файлов, шлюз к моделям).

**Данные.** PostgreSQL 16 на стенде, SQLite в тестах и локальной разработке
(один и тот же код через SQLAlchemy async). Файлы (видео, аудио, снимки,
резюме) — в локальном томе через абстракцию `Storage`, чтобы позже переехать
на S3-совместимое хранилище без переписывания сервисов.

**Фоновые задачи.** Таблица `jobs` + воркер в процессе API: извлечение аудио
(ffmpeg), транскрибация, оценка, integrity-анализ, синхронизация HH/Huntflow,
рассылка писем. Идемпотентные шаги, повторы с задержкой, видимый статус в UI.

**Модели.** Единый OpenAI-совместимый шлюз (AI Tunnel из РФ напрямую,
OpenRouter через egress-прокси) для LLM, STT (`/audio/transcriptions`) и TTS
(`/audio/speech`); ретраи, circuit breaker, keep-alive пул. Роли моделей
задаются настройками: `evaluator`, `assistant`, `interviewer`, `stt`, `tts`.

**Ассистент.** Цикл агента с инструментами (протокол `Toolbox`, реализуемый
сервисами), контекст открытой страницы, стриминг по SSE, необратимые действия —
только как «предложение», которое пользователь подтверждает кликом.

**Безопасность.** JWT для сотрудников, одноразовые токены-ссылки для кандидатов
и отчётов (хранятся хешем), API-токены с областями, шифрование OAuth-токенов
(Fernet), rate limiting на auth и публичных ручках, security-заголовки, аудит
изменений доступа, журнал согласий (текст версии, время, IP, user agent).

**Видео.** `MediaRecorder` по каждому вопросу (WebM/VP8+Opus в Chromium и
Firefox, MP4/H.264 в Safari), загрузка частями с докачкой, серверная
нормализация ffmpeg. Требование secure context: стенд работает по HTTPS.

## 4. Последовательность PR

Нумерация — порядок слияния. В скобках — что должно быть готово к концу шага.

### Фундамент

1. **Каркас репозитория** — план, README, лицензия, общие настройки. *(этот PR)*
2. **Бэкенд-скелет** — FastAPI, настройки, БД, Alembic, health, логирование с
   request-id, метрики, security-заголовки, тестовая инфраструктура, ruff.
3. **Фронтенд-скелет** — Next.js, тема LeonIT (акцент Napoleon IT `#140AF0`,
   Manrope), логотип LeonIT из вордмарка Napoleon IT, UI-кит, оболочка кабинета.

### Ядро продукта

4. **Аккаунты и доступы** — пользователи, организации, роли, приглашения по
   ссылке (срок, отзыв), смена роли, JWT, страницы входа/регистрации/участников.
5. **Вакансии и вопросы** — CRUD, требования и навыки, вопросы с типами
   (`video`, `code`), рубрика, настройки интервью; генерация и вычитка
   вопросов моделью.
6. **Шлюз моделей и фоновые задачи** — провайдеры LLM/STT/TTS, ретраи, breaker,
   прокси; воркер задач; страница проверки моделей.
7. **Кандидаты и приглашения** — кандидаты, ссылки-приглашения, страница
   согласий (имя, e-mail, ПДн, политика, рассылка), журнал согласий,
   юридические документы для Napoleon IT.
8. **Комната интервью** — проверка устройств и разрешений (матрица
   браузер/ОС), тренировочный вопрос, показ и озвучка вопроса, запись ответа,
   загрузка, прогресс, завершение.
9. **Медиа-пайплайн** — хранилище, докачка, ffmpeg, транскрибация с
   таймкодами, статусы обработки.
10. **ИИ-оценка** — структурированное заключение по вакансии (балл,
    рекомендация «подходит / не подходит / нужна проверка», пояснение, сильные
    стороны, зоны роста, риски, навыки, что проверить), growth-обратная связь
    кандидату, калибровка на примерах кейсодателя.
11. **Уточняющие вопросы** — решение «задать ли один уточняющий вопрос»,
    генерация, озвучка, запись, учёт в оценке.
12. **Integrity** — клиентские сигналы, снимки и подсчёт лиц, серверные
    анализаторы, integrity-score, предупреждения в отчёте.

### Работа с результатами

13. **Отчёты** — ранжирование по вакансии, карточка кандидата (видео с
    ускорением, транскрипт, саммари, скоры, резюме, диалог HH), заметки и
    решения ревьюеров, «слепой» режим, ссылка для нанимающего менеджера.
14. **Ассистент** — агент с инструментами, контекст страницы, подсказки под
    роль, история чатов, подтверждение необратимых действий.
15. **Дашборд** — метрики организации и вакансии.
16. **Публичный API** — токены с областями, версионированные ручки, исходящие
    вебхуки, документация Scalar.

### Интеграции и задел

17. **HH.ru** — OAuth, импорт вакансий и резюме, вебхуки и опрос откликов,
    диалог в чате HH с выбором слота, уникальная ссылка на интервью, связка
    кандидат ↔ отклик ↔ интервью; настройка сценария диалога через ассистента.
18. **Huntflow** — токен, синхронизация вакансий, передача кандидата и отчёта.
19. **Уведомления** — SMTP-абстракция с консольным фолбэком, письма:
    приглашение, напоминание, результаты, growth-обратная связь.
20. **ИИ-аватар и секция кода** — интерфейс провайдера аватара, место в UI
    интервью, тип вопроса `code` с редактором и интерфейсом раннера (за
    фиче-флагами).
21. **Лендинг** — страница для соискателей с видеодемо.

### Эксплуатация

22. **CI/CD** — GitHub Actions: проверки на hosted-раннере, сборка и выкат на
    self-hosted раннере сервера; compose, Caddy, миграции, health-чеки.
23. **Регрессионный e2e** — Playwright: сквозной сценарий кандидата и
    рекрутера, запись демо-видео для лендинга.
24. **Документация** — архитектура, runbook, описание проекта для сдачи.

## 5. Критерии готовности

- Сквозной сценарий из кейса проходится на стенде в ролях кандидата и рекрутера.
- Каждый PR зелёный в CI: ruff, mypy-совместимые типы, pytest, tsc, vitest,
  Playwright.
- Заключение по кандидату структурировано и аргументировано; рекомендация
  сходится с экспертной на тестовой выборке кейсодателя (цель ≥ 80 %).
- Полный цикл обработки интервью идёт без участия человека после настройки
  вакансии и вопросов.
