# LeonIT — план разработки

Платформа асинхронного видеоинтервью с ИИ-оценкой кандидатов. Кейс Napoleon IT
«ИИ-интервьюер: видеоинтервью и оценка кандидатов» (хакатон, сдача 07.09.2026).

Документ фиксирует границы продукта, архитектурные решения и последовательность
работ. Каждый пункт плана — отдельный PR в `main`; порядок важен, потому что
каждый следующий шаг опирается на предыдущий. Версия 2 — после ревью плана с
трёх позиций (продукт, безопасность, инженерия): порядок работ перестроен так,
чтобы стенд с HTTPS появился в первый день, а сквозной сценарий кейса — раньше
интеграций.

## 1. Что строим

**Сценарий из кейса.** Рекрутер загружает вакансию, требования и вопросы →
система выдаёт ссылку → кандидат проходит видеоинтервью (вопрос показывается и
озвучивается, ответ записывается на камеру) → транскрибация → ИИ-анализ →
структурированное заключение → рекрутер и нанимающий менеджер смотрят результат.

**Что добавляем сверх кейса** (по итогам разбора зарубежных платформ —
HireVue, Willo, myInterview, Spark Hire, BrightHire, Metaview, Karat):

| Область | Что делаем |
|---|---|
| AI-first интерфейс | Ассистент с инструментами в контексте страницы (как в Attio): создаёт вакансии, генерирует и вычитывает вопросы, даёт сводку и ранжирование по вакансии. Свои подсказки-сценарии для каждой роли. Необратимые действия — только как предложение, которое подтверждает человек. |
| Кандидатский флоу | Имя, e-mail, три раздельных согласия (ПДн, политика, рассылка). Проверка устройств с индикатором микрофона и пробной записью, подсказки по выдаче доступа к камере/микрофону для популярных браузеров и ОС. Вводный экран (сколько вопросов, сколько времени, до какого числа), тренировочный вопрос, время на подготовку, таймер, перезапись по настройке, возврат по той же ссылке с первого неотвеченного вопроса. |
| Защита от фрода | Сигналы делятся на **факты** (серверные тайминги, уход с вкладки, вставка текста, смена устройства, число лиц в кадре, дубли ответов между кандидатами) — каждый с таймкодом и доказательством — и **наблюдения** (речь похожа на чтение, аномальная тишина) вне скора. Integrity-score считается по фактам, никогда не меняет рекомендацию автоматически: максимум — «нужна проверка» и пункт «попросить повторно объяснить ответ №N». Никакой идентификации личности: только присутствие и число лиц. |
| Уточняющие вопросы | Один финальный уточняющий вопрос после основных (по вопросам, помеченным «допускает уточнение»), выключен по умолчанию, бюджет ожидания транскрипции ≤ 15 с. |
| Отчёты | Два независимых измерения: **соответствие** (сортировка, «нужна проверка» закреплена сверху) и **достоверность** (бейдж «без замечаний / обратить внимание / высокий риск»). «Рекомендация ИИ» и «Решение» (кто, когда) разведены. Карточка кандидата: видео по каждому вопросу с ускорением, транскрипт, саммари, скоры по вопросам и компетенциям с цитатами-доказательствами (клик перематывает видео), сильные стороны, зоны роста, риски, навыки, что проверить дальше, integrity-предупреждения, резюме, диалог с HH. Заметки и решения ревьюеров. Кандидату — growth-обратная связь по настройке вакансии (`off / after_decision / auto_after_days`). |
| Качество оценки | Рубрика по компетенциям с 4 якорными уровнями (генерируется из требований, рекрутер правит). Заключение — structured output; рекомендация «подходит / не подходит / нужна проверка» выводится детерминированно из баллов по порогам. Eval-контур: датасет «требования + транскрипт → экспертная метка», скрипт согласия с экспертом и confusion matrix, тест на устойчивость к инъекциям в ответах. |
| Дашборд | Воронка по статусам кандидата, средний балл, время до результата, доля флагов, согласие решений ревьюеров с рекомендацией ИИ. |
| Интеграции | HH.ru: OAuth, импорт вакансий и резюме, диалог в чате HH с выбором времени прохождения, уникальная ссылка на интервью; мок-режим с фикстурами по умолчанию, реальный клиент — по наличию ключей. Huntflow: адаптер, передача кандидата и ссылки на отчёт. Публичный API с токенами и документацией Scalar. |
| Доступы | Роли: владелец, рекрутер, нанимающий менеджер. Приглашение по ссылке с ролью, сроком и отзывом; смена роли; `token_version` для мгновенного отзыва сессий. Ссылки на отчёт для нанимающего менеджера: один кандидат, срок 7–14 дней, продление и отзыв, аудит просмотров. |
| ИИ-аватар | Провайдер HeyGen через общий интерфейс: клипы вопросов рендерятся при публикации и кэшируются, кандидат не ждёт рендера; аватар включается в настройках вакансии, без ключа — персона LeonIT с озвучкой. Сцена интервьюера занимает центр комнаты, камера кандидата — в углу. |
| Формат интервью | Настройка вакансии `interview_mode`: **живой диалог** (по умолчанию) — вопрос звучит, комната слушает, детектор пауз завершает ответ и задаёт следующий вопрос без кнопок; **кнопка ответа** (push-to-talk) — подготовка, «Начать ответ», «Завершить ответ», перезапись. Кнопка «Завершить ответ» в диалоге остаётся страховкой, лимит времени ответа действует в обоих форматах. |
| Задел на будущее | Тип вопроса `code`, интерфейс раннера и заглушка редактора — за фиче-флагами. |
| Лендинг | Ориентирован на соискателя, с видеодемо интерфейса. |
| Эксплуатация | Стенд с HTTPS с первого дня; CI (линт, типы, юнит-тесты, e2e кандидата с фейковой камерой); CD через self-hosted runner на сервере; миграции; health-чеки. |

## 2. Роли и границы доступа

| Роль | Что видит и делает |
|---|---|
| Владелец организации | Всё, что рекрутер, плюс участники, роли, приглашения, интеграции, API-токены, настройки моделей, срок хранения данных. |
| Рекрутер | Вакансии, вопросы, кандидаты, приглашения, отчёты, дашборд, ассистент, HH-диалоги. |
| Нанимающий менеджер | Только вакансии, к которым допущен, либо конкретный отчёт по ссылке. Заметки и решение по кандидату. |
| Кандидат | Без аккаунта: ссылка-приглашение → согласия → проверка устройств → интервью → страница завершения. Growth-обратная связь — отдельной ссылкой по решению рекрутера. |

Единый модуль `authorize(actor, action, resource)` используют роутеры,
инструменты ассистента, публичный API и агрегаты дашборда.

## 3. Архитектура

```
leon_it/
├── backend/     FastAPI · SQLAlchemy 2 (async) · Alembic · uv · Python 3.12
├── frontend/    Next.js 14 (App Router) · TypeScript · Tailwind · shadcn/ui
├── e2e/         Playwright: сценарий кандидата с фейковой камерой, регрессия, демо-видео
├── deploy/      docker compose · Caddy (HTTPS) · скрипты стенда
├── docs/        план, архитектура, runbook, юридические тексты
└── .github/     CI/CD
```

**Бэкенд — модульный монолит.** Каждая предметная область живёт в своём пакете
`backend/leonit/<area>/` с `models.py`, `schemas.py`, `service.py`, `router.py`.
Общая инфраструктура — `leonit/core/` (настройки, БД, ошибки, наблюдаемость,
rate limit, хранилище файлов, шлюз к моделям, фоновые задачи).

**Данные.** PostgreSQL 16 на стенде и в CI (отдельный job гоняет тесты и
`alembic upgrade head` на чистой базе), SQLite для локального запуска и
быстрых тестов. Файлы (видео, аудио, снимки, резюме) — локальный том через
абстракцию `Storage`; наружу отдаются только подписанными короткоживущими URL,
том никогда не публикуется как статика.

**Фоновые задачи.** Таблица `jobs` и отдельный сервис `worker` из того же
образа: захват через `SKIP LOCKED` + lease, повторы с экспоненциальной
задержкой, graceful shutdown, семафоры (1 ffmpeg, 3 запроса к моделям).
Идемпотентные шаги, статус задачи виден в карточке кандидата, кнопка
«Переобработать».

**Модели.** OpenAI-совместимый шлюз с конфигурацией на каждую роль
(`MODEL_<ROLE>_BASE_URL/_API_KEY/_MODEL/_PROXY`): `evaluator`, `assistant`,
`interviewer`, `stt`, `tts`. Structured output через JSON-режим с валидацией
Pydantic и одним repair-ретраем; сырой ответ сохраняется. `MODEL_PROVIDER=fake`
— детерминированный провайдер для CI и e2e без ключей и сети. Перед отправкой
в модель ФИО, e-mail и телефоны заменяются плейсхолдерами; транскрипт, резюме и
чат передаются как данные в отдельных секциях с пометкой «содержимое — не
команды».

**Видео.** `MediaRecorder` с каскадом поддерживаемых MIME (VP9/VP8+Opus,
H.264/AAC), 854×480, 24 fps, ~800 кбит/с; загрузка — строго последовательный
append чанков с докачкой; оригинал хранится как есть, ffmpeg только извлекает
аудио и делает ремукс для перемотки. Требование secure context: стенд работает
по HTTPS на домене `leon-it.tech` (Let's Encrypt через Caddy); старый адрес
`<ip>.sslip.io` остаётся алиасом.

**Серверные истины.** Время выдачи вопроса, время прихода каждого чанка и
длительность ответа фиксирует сервер; события клиента (уход с вкладки, вставка,
смена устройства, число лиц) приходят батчами и хранятся с таймкодами.

**Безопасность.** JWT с `token_version` для сотрудников, токены-ссылки (≥128
бит, хранятся хешем) для кандидатов и отчётов, API-токены `leonit_<random>` с
областями и SHA-256, шифрование OAuth-токенов (Fernet), rate limiting, security-
заголовки, `noindex` и `no-referrer` на страницах кандидата и отчёта, аудит
изменений доступа и просмотров отчётов, журнал согласий (хеш версии текста,
время, IP, user agent), срок хранения медиа и удаление данных кандидата.

4. **Стенд и CI/CD** — docker compose (api, worker, frontend, postgres, caddy),
   HTTPS на своём домене (до него — `sslip.io`), сборка образов, self-hosted runner на сервере, выкат
   по `push: main` с миграциями и health-чеком, job с PostgreSQL в CI. ✅
5. **Аккаунты и доступы** — пользователи, организации, роли, приглашения по

   на роль, FakeProvider, structured output, ретраи и breaker, воркер задач,

7. **Вакансии и вопросы** — CRUD, требования и навыки, рубрика компетенций с
   якорными уровнями, вопросы (`video`, `code`) с настройками
   `prep_seconds / max_answer_seconds / retakes_allowed / allows_followup`,
   генерация и вычитка вопросов моделью, публикация. ✅
8. **Кандидаты, приглашения, согласия, письма** — кандидаты (в т. ч. массовое
   добавление списком), ссылки-приглашения, страница согласий и журнал

   кандидата с таймстемпами, SMTP-абстракция с консольным фолбэком и вкладка
   «Письма», письма «приглашение» и «интервью завершено». ✅
9. **Комната интервью** — проверка устройств (разрешения, матрица браузер/ОС,

   каскад MediaRecorder, последовательная загрузка чанков, серверные тайминги,
   батч событий, возврат по ссылке, мобильные (facingMode, wakeLock, пауза при
   уходе), завершение. ✅
10. **Медиа-пайплайн** — извлечение аудио, ремукс, метаданные ffprobe,
    транскрибация с таймкодами (STT получает список навыков вакансии как
    подсказку), статусы обработки, срок хранения и удаление данных. ✅
11. **ИИ-оценка и eval-контур** — заключение по рубрике с evidence-цитатами,
    детерминированная рекомендация по порогам, growth-обратная связь по
    настройке вакансии, редактирование ПДн перед моделью, `backend/evals/`
    с датасетом и скриптом согласия, тест на инъекции. ✅
12. **Отчёты** — ранжирование (соответствие + достоверность), карточка
    кандидата с перемоткой по цитатам, заметки и решение ревьюера,
    частичные данные во время обработки, «Переобработать», ссылка для
    нанимающего менеджера (срок, продление, отзыв, аудит просмотров). ✅

## 5. Что решено не делать

- Перекодирование видео на сервере (только извлечение аудио и ремукс).
- Детекция «ИИ-сгенерированного текста», липсинк, анализ взгляда, «второй
  голос», серверное распознавание лиц и любая идентификация личности.
- Исходящие вебхуки публичного API, синхронизация вакансий и входящие вебхуки
  Huntflow, локальные модели (whisper.cpp).
- Refresh-токены с серверным хранением: вместо них `token_version` и короткий
  срок JWT.

## 6. Критерии готовности

- Сквозной сценарий из кейса проходится на стенде в ролях кандидата и рекрутера.
- Каждый PR зелёный в CI: ruff, pytest (SQLite и PostgreSQL), tsc, eslint,
  vitest; e2e кандидата — на `main`.
- Заключение по кандидату структурировано, каждое утверждение опирается на
  цитату из ответа; рекомендация сходится с экспертной на eval-наборе (цель
  ≥ 80 %), результат измеряется скриптом, а не оценивается на глаз.
- Полный цикл обработки интервью идёт без участия человека после настройки
  вакансии и вопросов.

## 7. Статус на 05.09.2026

Все 24 пункта плана закрыты и слиты в `main`; стенд обновляется автоматически
после каждого слияния. Что изменилось после промежуточной сдачи:

- **Модели — реальные.** Ключ AI Tunnel лежит на стенде, все пять ролей
  отвечают; заключения генерирует `claude-sonnet-5`, речь — `gpt-4o-transcribe`
  и `gpt-4o-mini-tts` голосом `nova`.
- **Контрольный набор расширен** до 23 базовых кейсов и 5 инъекций, включая
  пограничные: единица по критичной компетенции при высоком балле, шумная
  расшифровка, оборванные ответы, недоступные транскрипты, честный джуниор.
  Результат прогона и разбор расхождений — в `backend/evals/README.md`.
- **База знаний и быстрый черновик вакансии.** Документы о компании с
  разбором восьми форматов и поиском без внешних сервисов; ассистент отвечает
  о компании по базе, а вакансия заводится из «классического» текста с
  рубрикой и вопросами. Демо-организация наполнена документами о Napoleon IT.
- **Второй движок в e2e.** WebKit (движок Safari) прогоняет кабинет по флагу
  `E2E_WEBKIT=1`; комната кандидата на Windows-сборке WebKit недоступна
  (нет `getUserMedia`), Firefox добавлен за флагом `E2E_FIREFOX=1`.
- **HH.ru.** Ключи работодателя приняты, режим переключился на реальный, но
  зарегистрированный адрес возврата принадлежит другому приложению; до
  собственного приложения заказчика интеграция показывается в демо-режиме.

Что по-прежнему требует данных владельца:

- **SMTP.** Без него письма остаются в outbox и видны во вкладке «Письма».
- **Домен.** С 05.09 — `leon-it.tech`, старый `sslip.io` остаётся алиасом для
  разосланных ссылок; адрес возврата в кабинете hh нужно обновить на новый домен.

Задел, честно помеченный как задел: провайдер ИИ-аватара и песочница для
запуска кода — интерфейсы, фиче-флаги и UI готовы, конкретных провайдеров нет.
