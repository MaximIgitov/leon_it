# Юридические тексты кандидатского флоу

> Сами тексты лежат в `backend/leonit/legal/documents/` — так они попадают в образ
> бэкенда и отдаются через `GET /api/legal/{slug}`; здесь — правила их ведения.

Тексты, которые кандидат видит и принимает перед интервью, и приложения к
ним. Оператор персональных данных — ООО «Пример АйТи» (Example IT);
реквизиты в текстах указаны как есть, меняющиеся адреса вынесены в
плейсхолдеры.

## Состав

| Файл | Slug | Что это | Чекбокс на странице согласий |
|---|---|---|---|
| `backend/leonit/legal/documents/privacy-policy.md` | `privacy-policy` | Политика конфиденциальности (ст. 18.1 152-ФЗ) | Обязательный: «ознакомился(ась)» |
| `personal-data-consent.md` | `personal-data-consent` | Согласие на обработку ПДн, включая видео и голос (ст. 9 152-ФЗ) | Обязательный |
| `newsletter-consent.md` | `newsletter-consent` | Согласие на рассылку о вакансиях и новостях (ст. 18 38-ФЗ, ст. 15 152-ФЗ) | Необязательный, не предотмечен |
| `processors.md` | `processors` | Перечень обработчиков и категорий данных — приложение к политике | Без чекбокса, ссылка из текстов |

Три согласия оформлены отдельными документами и отдельными чекбоксами
намеренно: с 1 сентября 2025 г. согласие на обработку ПДн нельзя встраивать
в другие документы, а согласие на рекламу по позиции ФАС не должно быть
предотмечено и не может быть условием получения услуги.

## Формат файла

Markdown с YAML-frontmatter. Файл отдаётся на страницу `/legal/<slug>` как
есть — без правок на лету, кроме подстановки плейсхолдеров.

| Поле | Обязательное | Назначение |
|---|---|---|
| `title` | да | Заголовок страницы и подпись в журнале согласий |
| `slug` | да | Сегмент URL и ключ документа в журнале |
| `version` | да | Версия текста; используем дату `YYYY-MM-DD`, при двух правках в день — `YYYY-MM-DD.2` |
| `effective_date` | да | С какой даты действует редакция |
| `operator` | да | Наименование оператора — для подписи на странице |
| `required` | для согласий | `true` — без отметки кнопка «Продолжить» неактивна; `false` — необязательный |
| `checkbox_label` | для согласий | Текст рядом с чекбоксом; сам документ открывается по ссылке из этого текста |

### Плейсхолдеры

Подставляются при рендере; в файлах остаются как `{{NAME}}`, чтобы хеш
версии не зависел от стенда.

| Плейсхолдер | Откуда берётся значение | По умолчанию |
|---|---|---|
| `{{SITE_URL}}` | `PUBLIC_URL` из настроек бэкенда | `https://leon-it.tech` на стенде |
| `{{SUPPORT_EMAIL}}` | Настройка организации «e-mail поддержки» | `info@example.com` |
| `{{RETENTION_DAYS}}` | Настройка организации «срок хранения медиа», дней | `180` |

`{{RETENTION_DAYS}}` не может превышать 365: срок согласия — один год после
интервью, и медиа не должны переживать его. Валидатор настройки обязан это
проверять. Все прочие сроки (1 год, 3 года, 30 дней, 10 рабочих дней)
прописаны в текстах как есть и меняются только новой редакцией.

## Как тексты используются в продукте

### Страницы `/legal/...`

- `/legal/<slug>` — действующая редакция. В шапке: заголовок, версия, дата
  начала действия, оператор; в подвале — SHA-256 текста (первые 12 символов),
  чтобы кандидат мог сверить его с тем, что записано в журнале.
- `/legal/<slug>/versions` — список редакций со ссылками.
- `/legal/<slug>/<version>` — конкретная редакция из архива (см. ниже).
- Страницы отдаются с `noindex`; ссылки на них не требуют аутентификации.

### Страница согласий кандидата

Порядок на странице: имя и e-mail → три чекбокса → кнопка «Продолжить».

1. `personal-data-consent` — обязательный.
2. `privacy-policy` — обязательный («ознакомился(ась)»).
3. `newsletter-consent` — необязательный, не отмечен, подпись содержит слово
   «необязательно».

Ни один чекбокс не предотмечен. Кнопка активна только при двух обязательных
отметках. Рядом с чекбоксом — ссылка на полный текст в новой вкладке; текст
чекбокса берётся из `checkbox_label`. На странице показывается название
вакансии из приглашения, потому что согласие ссылается на «вакансию, указанную
на странице приглашения».

Если кандидат возвращается по той же ссылке, а действующая редакция
обязательного документа новее принятой, страница согласий показывается
снова — только для изменившихся документов.

### Журнал согласий

На каждую отметку — отдельная запись; отзыв — отдельная запись со ссылкой на
исходную. Поля:

| Поле | Значение |
|---|---|
| `candidate_id`, `invitation_id` | Кто и по какой ссылке |
| `document_slug`, `document_version` | Из frontmatter |
| `document_hash` | SHA-256 файла (см. ниже) |
| `placeholders` | JSON с фактическими значениями плейсхолдеров на момент отметки, например `{"SITE_URL": "...", "RETENTION_DAYS": 180}` |
| `accepted_at` | Серверное время UTC |
| `ip`, `user_agent` | Из запроса |
| `email` | E-mail, введённый на странице (совпадает с приглашением, если ссылка персональная) |
| `withdrawn_at`, `withdrawal_note` | Заполняются при отзыве; отзыв фиксирует сотрудник по письму кандидата |

Записи журнала — доказательство факта согласия (ч. 3 ст. 9 152-ФЗ), поэтому
они не удаляются вместе с данными кандидата и хранятся 3 года после
прекращения обработки, как обещано в текстах. Значения плейсхолдеров
записываются отдельно, чтобы по журналу можно было воспроизвести текст,
который кандидат реально видел.

### Хеш версии

`document_hash` = SHA-256 от байтов файла целиком, включая frontmatter, в
UTF-8 без BOM с переводами строк LF (так файл и лежит в репозитории:
`.gitattributes` задаёт `eol=lf`). Бэкенд нормализует CRLF → LF перед
подсчётом на случай чтения с Windows-диска. Проверить вручную:

```bash
cd backend
python -m uv run python -c "import hashlib,sys;print(hashlib.sha256(open(sys.argv[1],'rb').read().replace(b'\r\n',b'\n')).hexdigest())" ../docs/legal/personal-data-consent.md
```

Бэкенд читает файлы из `docs/legal/` при старте (в образе каталог копируется
рядом с приложением), парсит frontmatter, считает хеш и отдаёт всё это
фронтенду одной ручкой. Тест на стороне бэкенда должен проверять, что у
каждого файла заполнены обязательные поля, `version` уникален в пределах
slug и в тексте встречаются только известные плейсхолдеры.

## Как обновить редакцию

1. Скопировать текущий файл в `archive/<slug>/<version>.md` (каталог
   создаётся при первом обновлении) — так страница `/versions` отдаёт старые
   редакции без обращения к git.
2. Внести правки в основной файл, поднять `version` и `effective_date`.
   Дата начала действия не может быть раньше даты выкладки.
3. Решить, существенное ли изменение. Существенное — новая цель, новая
   категория данных или получателей, новая страна передачи, увеличение срока
   хранения. Тогда:
   - кандидатам, чьи данные ещё обрабатываются, уходит письмо об изменениях;
   - обязательные согласия запрашиваются заново при следующем визите по
     ссылке (см. выше);
   - в `processors.md` при смене обработчика обновляется таблица и раздел
     «Страны».
   Редакционные правки (опечатки, формулировки без изменения смысла)
   согласия заново не требуют.
4. Согласованные тексты изменяются одним PR с пометкой `docs(legal)`, чтобы
   в истории git была видна каждая редакция и её автор.

Тексты в `personal-data-consent.md` и `backend/leonit/legal/documents/privacy-policy.md` должны совпадать
по срокам и по составу обработчиков с `processors.md` — при правке одного
проверяйте остальные.

## Что должен сделать оператор помимо текстов

Тексты не заменяют организационных обязанностей ООО «Пример АйТи» по
152-ФЗ. Чек-лист перед запуском на реальных кандидатах:

- уведомление Роскомнадзора об обработке ПДн (ст. 22) — если ещё не подано
  или не покрывает цели подбора персонала и категорию «соискатели»;
- уведомление Роскомнадзора о трансграничной передаче (ст. 12) **до**
  включения провайдеров STT/LLM за пределами России; до решения РКН —
  `MODEL_PROVIDER=fake` либо российский провайдер;
- письменные поручения на обработку с обработчиками из `processors.md`
  (ч. 3 ст. 6: перечень действий, цели, обязанность соблюдать
  конфиденциальность и меры защиты по ст. 19);
- назначение ответственного за организацию обработки (ст. 22.1) и внутренние
  документы: политика, перечень мер по ст. 18.1;
- проверка, что настройка `MODEL_<ROLE>_BASE_URL` каждой роли ведёт к
  провайдеру из `processors.md`, а `RETENTION_DAYS` ≤ 365.

## Известные оговорки

- **Реквизиты AI Tunnel.** В задании посредник обозначен как ООО; на сайте
  aitunnel.ru оператором указан ИП Агафонов Н. А. (ИНН 692499040700). В
  тексте оставлены данные с сайта — перед публикацией сверить с договором.
- **Трансграничная передача в США.** П. 1 ч. 8 ст. 12 152-ФЗ требует для
  стран без адекватной защиты согласия в письменной форме. Тексты решают это
  через простую электронную подпись (чекбокс + журнал, п. 9 согласия), как
  это делают онлайн-сервисы, но практика надзора неоднородна. Надёжная
  альтернатива — STT/LLM с размещением в России; тогда раздел 8 политики,
  п. 3 раздела 4 согласия и раздел 5 перечня сокращаются новой редакцией.
- **Один оператор.** Тексты написаны для Example IT как единственного
  работодателя на Платформе. Если Платформу начнут использовать другие
  организации, каждая из них — самостоятельный оператор: понадобится
  шаблон с полями реквизитов и договор между Example IT и такой
  организацией.
- **Почтовый сервис.** Внешний SMTP-провайдер пока не выбран; строка № 5 в
  `processors.md` описывает почтовую инфраструктуру оператора и подлежит
  уточнению при подключении.
- **hh.ru и Huntflow** описаны с оговоркой «если интеграция подключена» —
  фактическая передача начинается только после включения интеграции.
- Тексты подготовлены без участия юриста и требуют проверки перед
  использованием с реальными кандидатами.
